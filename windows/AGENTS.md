# windows/ — Berpiztu AI Keyboard for Windows

## Purpose

- A Windows app (.NET 10, WPF, `net10.0-windows10.0.19041.0`) with the standard keyboards, Estándar and Estándar PC, and those designed from them, in a floating card that never takes the focus from the window typed in, its keys sent to that window

## Ownership

- This file owns `windows/`; the layouts, the design format, the keyboards' record and the keys' signs it uses belong to the root (`StandardKeys.cs`, `StandardDesign.cs`, `KeyboardEntry.cs`, `Resources/drawable/`)

## Local Contracts

- `Berpiztu.KeyPlus.Windows.csproj` compiles `..\StandardKeys.cs`, `..\StandardDesign.cs` and `..\KeyboardEntry.cs` as they are and copies the signs it draws (`..\Resources\drawable\ic_key_*.xml`, `ic_grid_pc`, `ic_grid_phone`, `ic_grid_design`, `ic_tool_*`) beside the app, under `drawable\`; the root csproj leaves `windows\**` out of the Android build
- `AndroidNames.cs` defines the Android names the shared files use (`Android.Views.Keycode` with Android's values, `Android.Util.Log.Warn` to the keyboard's log, `Resource.Drawable` and `Resource.String` ids); a name added to them is added there too, and a sign there joins `Icons.cs`'s files and the csproj's copied ones
- `KeyboardSurface.cs` lays out, draws and types as the Android `StandardKeyboard.cs` does, with the same sizes (one Android dp a WPF unit); a change of behaviour there is made here too
- `KeySender.cs` sends with `SendInput`: text as Unicode characters, other keys by virtual key with Ctrl, Alt, ⊞ and Shift around them
- `KeyboardWindow.cs`: a Windows window, no docking: moved by Windows (`DragMove`) from the toolbar and the handle, resized at its edges and corners by Windows (`WindowChrome`, the shadow's band), the keys' rows growing and shrinking with its height (`KeyboardSurface.RowScale`, half Gboard's at least), kept per row scale so Estándar and PC keep their rows' height; `WS_EX_NOACTIVATE` (never focused) and `WS_EX_APPWINDOW` (a taskbar button), set by `NeverActivated.cs`; its place, width, row scale, language and its icon's place kept in `%APPDATA%\Berpiztu\Keyboard\window.json`; as Android's, it shows when a text field takes the focus (`FocusWatch.TextFocused`: an editable text, or a caret soon after the focus moved) and hides, becomes its ⌨ icon (`KeyboardIconWindow.cs`, Android's look) or stays when the focus leaves, as the preferences say; opened by hand it stays until a text field takes the focus; ✕ and the taskbar's close hide it, and only Salir on the icon by the clock (`TrayIcon.cs`, Windows Forms' NotifyIcon) ends it; started again, the program shows the running keyboard (a registered window message)
- Keyboards: `Keyboards.cs`, Android's list on Windows: Estándar, Estándar PC and those saved (`KeyboardEntry`, each with its `StandardDesign` as JSON) in `%APPDATA%\Berpiztu\Keyboard\keyboards.json`; the one shown is `preferences.json`'s `Keyboard` id (an older file's `Pc` read as Estándar or Estándar PC), so the settings and the keyboard share it through the preferences' watch; the toolbar's switch, as Android's, shows a phone for Estándar and a computer for any other, a click Estándar PC from Estándar and Estándar from any other
- Diseñar (the toolbar's `ic_grid_design`): Android's designer, `KeyboardSurface`'s `Design`, `Designing`, `ResizeMarked`, `RemoveMarked`, `AddKey`, `AddRow`, `AddColumn` as `StandardKeyboard.cs`'s, a click marking and a drag past Android's 8 dp slop moving, a key let go on a hole (`StandardKeys.Gap`, + Columna's) filling it; the designer's pills (`PillButton`) in the toolbar's place and + Tecla's list in the keys' place, in `KeyboardWindow.cs`: of `StandardKeys.Extras` only those the keyboard lacks (`StandardKeys.HasExtra`, shared), the one chosen loose over the keys (`AddKey`) until dragged and let go into a row; Hecho saves a built-in keyboard as a new one, shown at once, and a saved one in its place; a design with more or fewer rows makes the window as tall as they need (`RowsChanged`), the rows keeping their height; while designing the focus leaving never hides the keyboard and the preferences never change the keyboard shown
- `Palette.cs`: the colours from Windows' accent tones and the theme's background and foreground (`UISettings`), never written by hand
- `Program.cs`: one keyboard at a time (a mutex); `--settings` starts the settings, `--hidden` the keyboard out of sight (as the installer starts it at sign-in); the version is the Android apps' (read from `..\Berpiztu.KeyPlus.csproj`) and the icon `BerpiztuKeyboard.ico` (`..\packaging\Make-WindowsIcon.ps1`)
- `Texts.cs`: the words are the Android keyboard's `strings.xml` (values, values-es), copied beside the app, read by an id's name; `AndroidNames.cs`'s `Resource` fields are named as the Android resources, and `Icons` and `Texts` find a file or a text by that name
- 🎤: `..\VoiceTyping.cs` (shared with Android) hears `NAudioMicrophone.cs` (NAudio, 16 kHz mono, the microphone set), raises it by the gain and sends it to ia-voice, the owner's speech service (OpenAI's `/v1/audio/transcriptions`, NVIDIA Nemotron 3.5 ASR), with the keyboard language's locale (`StandardLanguage.Locale`, es-ES or en-US: the service refuses a bare es): this computer's container (Local, `http://127.0.0.1:8060`), one on the local network by its IP (Red local: http and port 8060 unless written, `VoiceTyping.LanService`), or a published one at an address (Remoto), signing in at wslc's publish proxy (`/__login/api/login`, a cookie) with the user and password set; while listening, all heard so far is sent again every second and its words typed in the field as they come, only what changed deleted and typed again (`KeyboardSurface.TypeSpokenSoFar`); 🎤's circle beats with the level; it listens until 🎤 is tapped again, or, with Parar solo al dejar de hablar on (off by default), after speaking the set silence stops it, heard as a level under speech's (0.12, IA-BotMsgs' chat's) or read as no new word for as long, for microphones whose own noise is above that (Remote Desktop's); the window leaves the top until the first sound, so Windows' microphone question is not hidden under it
- ⚙: `SettingsWindow.cs` with Android's pages that apply (Idiomas, Preferencias, Tema: the keyboards of the list, those saved renamed as their name is written or deleted once asked, Escritura deslizando el dedo, Escribir por voz, Solución de problemas, Información); the keyboard, its language and swiping are kept in `preferences.json` too, written by the settings and by the keyboard's own buttons, the keyboard taking them at once; the settings as an app of their own, as on Android: the same program started with `--settings`, a process apart (one of each at a time, `Program.cs`), so closing the keyboard leaves them open and the keyboard types in them as in any window; Android's pages and words, each change kept at once: Preferencias (`KeyboardPreferences.cs`, `preferences.json`: Apartarse del texto) and Escribir por voz (`VoiceSettings.cs`, `voice.json`: microphone, stopping by itself or not and after how long a silence (0.5–30 s), gain ×1–×4, Local, Red local with its IP or Remoto with address, user and password, the password sealed for the Windows user with DPAPI; the browser's noise suppression, echo cancellation and automatic gain have no WinMM counterpart and are left out)
- Apartarse del texto: `FocusWatch.cs` follows, in any window, the caret and the open menus as Windows' Magnifier does (WinEvents: OBJID_CARET shown or moved; a menu popup started, or a menu item focused, as Chromium's menus in VS Code and Edge are; `IAccessible.accLocation` for their place); the text kept clear of is the focused field where the keyboard fits above or below it, else (an editor) the caret's line across the field (`KeyboardWindow.AvoidText`, Android's `KeyPlusKeyboard.Avoided` the same); one under the card, the keyboard moves above it where there is room, else below it, 16 dp away, else to the side with more room, and stays there, as on Android; a menu moves it once and it then stays still while that menu is open, so its keys can be reached (Apartarse también de los menús, an option of its own, `AvoidMenus`); the settings' change is seen at once through `preferences.json` (`KeyboardPreferences.Watch`)
- Emoji: `EmojiPanel.cs` (the Android panel's layout), the list from `..\EmojiList.cs` (shared with Android) without Flags, which Windows does not draw; `EmojiArt.cs` draws each emoji in colour with Direct2D and DirectWrite (Vortice.Direct2D1), WPF's own text drawing them black and white; the recent ones in `%APPDATA%\Berpiztu\Keyboard\recent-emoji.txt`; opened by the comma held or ☺ on the toolbar
- Words as you type: `..\WordSuggestions.cs` (shared with Android) from the language's word list beside the app, read the first time; Windows tells a keyboard nothing of the field, so the word being typed is the keys' own count (`KeyboardSurface.typingWord`), begun again by anything but a letter or ⌫; the words offered show in the toolbar, the likeliest in the centre, a tap taking one with a space
- Swipe typing: `SwipeEngine.cs` calls `keyplus_swipe.dll` (`native/futo-swipe/win-x64/`, built by `native/futo-swipe/windows/build.ps1` from FUTO's swipe-library and ExecuTorch with clang-cl, its C API in `keyplus_swipe.cpp`); the encoder and the word lists are the Android keyboard's `Assets/`, copied beside the app; the words are made with `..\SwipeWords.cs`, shared with Android; the letter forms are written to `%LOCALAPPDATA%\Berpiztu\Keyboard\futo-swipe`

## Work Guidance

- Not on Windows yet, saying so where asked: the grid, the clipboard, the emoji's recent row
- VS Code (Electron) tells its menus, and its focus inside the page, only while its accessibility is on, which Electron turns on when something asks as a screen reader would and keeps until VS Code closes; the keyboard asks each window coming to the front (`FocusWatch.Awaken`: MSAA and UI Automation, Chromium's page windows too), which wakes Edge and Chrome but not VS Code. VS Code is started with `--force-renderer-accessibility` for its menus to be avoided: on the owner's PC it is in VS Code's Start menu and taskbar shortcuts (set 2026-10-23, the originals kept in the session's scratchpad); a VS Code update may write the Start menu shortcut again without it, and then menus in VS Code stop moving the keyboard until it is put back. The settings' Solución de problemas says so and puts it in the user's VS Code shortcuts with a button (`ElectronShortcuts.cs`: the Start menu's, the taskbar's and the desktop's that start Code.exe), and shows where the keyboard's log is
