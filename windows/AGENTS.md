# windows/ — Berpiztu AI Keyboard for Windows

## Purpose

- A Windows app (.NET 10, WPF, `net10.0-windows10.0.19041.0`) with the standard keyboards, Standard and Standard PC, and those designed from them, in a floating card that never takes the focus from the window typed in, its keys sent to that window

## Ownership

- This file owns `windows/`; the layouts, the design format, the keyboards' record and the keys' signs it uses belong to the root (`StandardKeys.cs`, `StandardDesign.cs`, `KeyboardEntry.cs`, `Resources/drawable/`)

## Local Contracts

- `Berpiztu.KeyPlus.Windows.csproj` compiles `..\StandardKeys.cs`, `..\StandardDesign.cs` and `..\KeyboardEntry.cs` as they are and copies the signs it draws (`..\Resources\drawable\ic_key_*.xml`, `ic_grid_pc`, `ic_grid_phone`, `ic_grid_design`, `ic_tool_*`) beside the app, under `drawable\`; the root csproj leaves `windows\**` out of the Android build
- `AndroidNames.cs` defines the Android names the shared files use (`Android.Views.Keycode` with Android's values, `Android.Util.Log.Warn` to the keyboard's log, `Resource.Drawable` and `Resource.String` ids); a name added to them is added there too, and a sign there joins `Icons.cs`'s files and the csproj's copied ones
- `KeyboardSurface.cs` lays out, draws and types as the Android `StandardKeyboard.cs` does, with the same sizes (one Android dp a WPF unit); a change of behaviour there is made here too
- `KeySender.cs` sends with `SendInput`: text as Unicode characters, other keys by virtual key with Ctrl, Alt, ⊞ and Shift around them; a character under Ctrl, Alt or ⊞ with no key code of its own (`KeyboardSurface.CodeOf`) by the key that types it in the keyboard language's Windows layout (`VkKeyScanEx`; the layout among those installed by the language's LCID, never loaded, else the foreground window's; none with Alt Gr), so Spanish's ç is VK_OEM_2, as a physical keyboard's
- `KeyboardWindow.cs`: a Windows window, no docking: moved by Windows (`DragMove`) from the toolbar and the handle, resized at its edges and corners by Windows (`WindowChrome`, the shadow's band), the keys' rows growing and shrinking with its height (`KeyboardSurface.RowScale`, half Gboard's at least), kept per row scale so Standard and PC keep their rows' height; `WS_EX_NOACTIVATE` (never focused) and `WS_EX_APPWINDOW` (a taskbar button), set by `NeverActivated.cs`; its place, width, row scale, language and its icon's place kept in `%APPDATA%\Berpiztu\Keyboard\window.json`; as Android's, it shows when a text field takes the focus (`FocusWatch.TextFocused`: an editable text, a caret soon after the focus moved, or a caret still shown in the window the focus went to, as VS Code's editor come back to, which tells only a pane) and hides, becomes its ⌨ icon (`KeyboardIconWindow.cs`, Android's look) or stays when the focus leaves, as the preferences say; opened by hand it stays until a text field takes the focus; ✕ and the taskbar's close hide it, and after ✕ the text tapped or clicked again brings it back, as Android's (the focus stays, so only the caret moves: within 600 ms of a press it shows, typing moves it with none; the presses noted by `PointerWatch.cs`, a low-level mouse hook on a thread of its own, kept only until the keyboard shows), and only Quit on the icon by the clock (`TrayIcon.cs`, Windows Forms' NotifyIcon) ends it; started again, the program shows the running keyboard (a registered window message)
- Keyboards: `Keyboards.cs`, Android's list on Windows, by language (a PC's keys differ between them): Standard and Standard PC in every language (Standard PC with the language's design, `StandardKeys.PcDesign`, shared: Spanish's and English's the owner's), and those saved (`KeyboardEntry`, each with its `StandardDesign` as JSON and the language it was designed in, none read as Spanish) in `%APPDATA%\Berpiztu\Keyboard\keyboards.json`; each language shows the one chosen for it, `preferences.json`'s `Chosen` (language → id; an older file's `Keyboard` read as Spanish's, its `Pc` as Standard or Standard PC), 🌐 changing the keyboard with the language, the kind in sight kept (`Keyboards.Carry`: Standard stays Standard, a PC's a PC's, the language's own where of that kind, as on Android); the settings and the keyboard share both files through their watches (`FileWatch.cs`); the toolbar's switch, as Android's, shows a phone for Standard and a computer for any other, a click Standard PC from Standard and Standard from any other
- Design (the toolbar's `ic_grid_design`): Android's designer, `KeyboardSurface`'s `Design`, `Designing`, `ResizeMarked`, `RemoveMarked`, `AddKey`, `AddRow`, `AddColumn` as `StandardKeyboard.cs`'s, a click marking and a drag past Android's 8 dp slop moving, a key let go on a hole (`StandardKeys.Gap`, + Column's) filling it; a marked Enter clicked again takes its next shape (`StandardKeys.EnterShapes`, `StandardDesign.Reshape`, shared, as on Android): it keeps its row, a shaped one's top going up into the row above right-aligned over it (`StandardKey.Below`), its own part laid as a `Lower` key, that row shifted to right-align it under its top, the two drawn joined (`DrawJoint`); a shaped Enter moved and removed whole (`StandardDesign.Put`/`Remove`); the designer's pills (`PillButton`) in the toolbar's place and + Key's list in the keys' place, in `KeyboardDesigner.cs`, the keyboard's and the settings' Theme's alike: of `StandardKeys.Extras` only those the keyboard lacks (`StandardKeys.HasExtra`, shared), the one chosen loose over the keys (`AddKey`) until dragged and let go into a row; Done saves a built-in keyboard as a new one of the language designed in, chosen for it at once, and a saved one in its place; a design with more or fewer rows makes the window as tall as they need (`RowsChanged`), the rows keeping their height; while designing the focus leaving never hides the keyboard and the preferences never change the keyboard shown
- Dock (the toolbar's `ic_grid_floating_off`/`ic_grid_floating`, Android's Floating sign): the keyboard docked at the bottom of the screen it is on as an app bar (`DockedBar.cs`, SHAppBarMessage; the bottom Windows gave kept, for asked again it counts the bar's own room as taken), the window held on it in WM_WINDOWPOSCHANGING (Windows would push it inside the work area, which leaves the bar out), the room given back while hidden; its keys never stretched: their own width centred (`dockedWidth`, `dockedOffset`, `dockedLift` in `window.json`), the bar's ground around; no shadow, corners, handle, edge resizing or moving out of the text's way; `preferences.json`'s `Docked`; the same keyboard as floating, its docked design where it has one (`KeyboardEntry.DockedDesign`, designed docked); Resize (`ic_tool_resize`) as Android's `KeyboardFrame.cs`, floating and docked: the keys dimmed, edges for the height and the width, ✥ to move, Reset (as made), Cancel (as the frame found it) and Done; every drag measured on the screen from where it began (`held`), never by summing the `Thumb`'s change, which is the whole way when the grip does not move with what it sizes; the height and, docked, the lift follow the drag, the bar shown so and asked of Windows once let go (`PlaceDocked(asked)`, each ask laying the other windows out again); the window no taller than the screen above the taskbar, the lift half of it at most, as Android's
- `Palette.cs`: the colours from Windows' accent tones and the theme's background and foreground (`UISettings`), never written by hand; Theme's Colours (`preferences.json`'s `Look`, `..\KeyboardLook.cs`, shared): System, Light or Dark (background and foreground change places), or Custom, the keyboard's colour in the background's place and the accent's in the accent's (`KeyColor`, `AccentColor`, #RRGGBB, chosen in Windows' colour picker; one not chosen, Windows' own; Undo, Custom's alone, takes the two back one step, `Before`; Per app, Custom's too (`PerApp`): each application typed in, by its program's name, with its window's colour (App's, as an application starts) or its own two (a keyboard colour not chosen Theme's Custom's, an accent Windows' own), in `apps.json` (`AppColors.cs`), the keyboard adding one the first time it types in it and keeping the window's colour it saw there, read once as the application is come to, just inside the focused field's corner (`SeenColor`), else the one seen last; the keyboard starts in the colours of the application in front (`FocusWatch.FrontApp`); Theme's Colours row in one line: the choice, Per app, the application, App's, the two colours, ↶), its tones a quarter of the way to white or black a step; every part takes its colours as it is made, so a change makes the keyboard again where it is (`KeyboardWindow.Remake`, the old one heeding no more changes: Windows tells a file's change several times; from a focus, once it has been told, for the old one closes its focus watch)
- Updates: `UpdateCheck.cs` over `..\Updates.cs` (shared): the keyboard looks every hour, a minute after it starts, and asks GitHub once a day while About's Check for updates automatically is on (`updates.json`: `Automatic`, `Checked`); Check now asks at once; a newer release is a message box asking whether to update, and a yes downloads the MSI to `%TEMP%` and opens it (`msiexec /i`, with its window, so it stops the keyboard and starts the new one); a check by itself that fails is only in the log, one asked for or after a yes is told
- `Program.cs`: one keyboard at a time (a mutex); `--settings` starts the settings, `--hidden` the keyboard out of sight (as the installer starts it at sign-in); the version is the Android apps' (read from `..\Berpiztu.KeyPlus.csproj`) and the icon `BerpiztuKeyboard.ico` (`..\packaging\Make-WindowsIcon.ps1`)
- `Texts.cs`: the words are the Android keyboard's `strings.xml` (values, values-es), copied beside the app, read by an id's name; `AndroidNames.cs`'s `Resource` fields are named as the Android resources, and `Icons` and `Texts` find a file or a text by that name
- 🎤: `..\VoiceTyping.cs` (shared with Android) hears `NAudioMicrophone.cs` (NAudio, 16 kHz mono, the microphone set), raises it by the gain and sends it to ia-voice, the owner's speech service (OpenAI's `/v1/audio/transcriptions`, NVIDIA Nemotron 3.5 ASR), with the keyboard language's locale (`StandardLanguage.Locale`, es-ES or en-US: the service refuses a bare es): this computer's container (Local, `http://127.0.0.1:8060`), one on the local network by its IP (Local network: http and port 8060 unless written, `VoiceTyping.LanService`), or a published one at an address (Remote), signing in at wslc's publish proxy (`/__login/api/login`, a cookie) with the user and password set; while listening, all heard so far is sent again every second and its words typed in the field as they come, only what changed deleted and typed again (`KeyboardSurface.TypeSpokenSoFar`); 🎤's circle beats with the level; it listens until 🎤 is tapped again, or, with Stop by itself when you stop speaking on (off by default), after speaking the set silence stops it, heard as a level under speech's (0.12, IA-BotMsgs' chat's) or read as no new word for as long, for microphones whose own noise is above that (Remote Desktop's); the window leaves the top until the first sound, so Windows' microphone question is not hidden under it
- ⚙: `SettingsWindow.cs` with Android's pages that apply (Languages, Preferences, Theme: by language, each part of one size whatever it holds so nothing moves (the language looked at and the keyboard as two lists, a name with Save as, which copies the keyboard chosen under it, and Delete for one saved), and the keyboard chosen drawn as the card shows it, a box of one size (the card's width, Standard PC's rows) zoomed with the page, only to be seen (`KeyboardSurface.Types` off), Design in its bar's place designing it there one to one, the list at the left hidden and the window made larger where it is smaller, Glide typing, Voice typing, Troubleshooting, About); the keyboard, its language and swiping are kept in `preferences.json` too, written by the settings and by the keyboard's own buttons, the keyboard taking them at once; the settings as an app of their own, as on Android: the same program started with `--settings`, a process apart (one of each at a time, `Program.cs`), so closing the keyboard leaves them open and the keyboard types in them as in any window; Android's pages and words, each change kept at once: Preferences (`KeyboardPreferences.cs`, `preferences.json`: Move out of the way of the text) and Voice typing (`VoiceSettings.cs`, `voice.json`: microphone, stopping by itself or not and after how long a silence (0.5–30 s), gain ×1–×4, Local, Local network with its IP or Remote with address, user and password, the password sealed for the Windows user with DPAPI; the browser's noise suppression, echo cancellation and automatic gain have no WinMM counterpart and are left out)
- Move out of the way of the text: `FocusWatch.cs`, on a thread of its own (its WinEvent hooks, its timers and every read of another application's accessibility, which waits for that application to answer; what it sees told to the keyboard's thread in order, nothing once disposed), follows, in any window, the caret and the open menus as Windows' Magnifier does (WinEvents: OBJID_CARET shown or moved; a menu popup started, or a menu item focused, as Chromium's menus in VS Code and Edge are; `IAccessible.accLocation` for their place); the text kept clear of is the focused field where the keyboard fits above or below it, else (an editor) the caret's line across the field (`KeyboardWindow.AvoidText`, Android's `KeyPlusKeyboard.Avoided` the same); one under the card, the keyboard moves above it where there is room, else below it, 16 dp away, else to the side with more room, and stays there, as on Android; a menu moves it once and it then stays still while that menu is open, so its keys can be reached (Also move out of the way of menus, an option of its own, `AvoidMenus`); the settings' change is seen at once through `preferences.json` (`KeyboardPreferences.Watch`)
- Emoji: `EmojiPanel.cs` (the Android panel's layout), the list from `..\EmojiList.cs` (shared with Android) without Flags, which Windows does not draw; `EmojiArt.cs` draws each emoji in colour with Direct2D and DirectWrite (Vortice.Direct2D1), WPF's own text drawing them black and white; the recent ones in `%APPDATA%\Berpiztu\Keyboard\recent-emoji.txt`; opened by the comma held or ☺ on the toolbar
- Words as you type: `..\WordSuggestions.cs` (shared with Android) from the language's word list beside the app, read the first time; Windows tells a keyboard nothing of the field, so the word being typed is the keys' own count (`KeyboardSurface.typingWord`), begun again by anything but a letter or ⌫; the words offered show in the toolbar, the likeliest in the centre, a tap taking one with a space
- Swipe typing: `SwipeEngine.cs` calls `keyplus_swipe.dll` (`native/futo-swipe/win-x64/`, built by `native/futo-swipe/windows/build.ps1` from FUTO's swipe-library and ExecuTorch with clang-cl, its C API in `keyplus_swipe.cpp`); the encoder and the word lists are the Android keyboard's `Assets/`, copied beside the app; the words are made with `..\SwipeWords.cs`, shared with Android; the letter forms are written to `%LOCALAPPDATA%\Berpiztu\Keyboard\futo-swipe`; ⌫ right after a swiped word deletes all the swipe typed while Glide typing's Delete a swiped word whole is on (`preferences.json`'s `GlideDeleteWord`, `KeyboardSurface.DeletesSwipedWord`), as Android's `swipeDeleteWord`
- Dictionary: `..\PersonalWords.cs` (shared) in `%APPDATA%\Berpiztu\Keyboard\personal-words.json`, the keyboard and the settings both writing it and the keyboard watching it (`FileWatch`): the words read with the word list into FUTO Swipe's trie (`SwipeEngine`'s personal words; `Forget` lets the tries go, `keyplus_swipe_destroy_trie`, only when the words change, never for a choice noted) and offered first as a word is typed; `KeyboardSurface.WordTyped` (a word ended by a space, a sign or Enter) learns one no list has (`WordSuggestions.Knows`) at its second time; `SwipeChosen` notes the toolbar's word taken for the word a swipe read first, and `PersonalWords.Ordered` puts the one chosen most first; the settings' Dictionary page has the two learning choices, Forget the words chosen, Export and Import (`PersonalWords.Export`/`Import`: a `berpiztu-dictionary` JSON of every language, Gboard's lines or a word a line; added, never taken away; a failure in a window and the log), the language, a word added, and last the words in a scrolling box of one size, each line with ✏ (written again in place: Enter keeps, Esc leaves) and a red ✕ (`KeyboardLooks.DeleteRed`)

## Work Guidance

- Not on Windows yet, saying so where asked: the grid, the clipboard, the emoji's recent row
- VS Code (Electron) tells its menus, and its focus inside the page, only while its accessibility is on, which Electron turns on when something asks as a screen reader would and keeps until VS Code closes; the keyboard asks each window coming to the front (`FocusWatch.Awaken`: MSAA and UI Automation, Chromium's page windows too), which wakes Edge and Chrome but not VS Code. VS Code is started with `--force-renderer-accessibility` for its menus to be avoided: on the owner's PC it is in VS Code's Start menu and taskbar shortcuts (set 2026-10-23, the originals kept in the session's scratchpad); a VS Code update may write the Start menu shortcut again without it, and then menus in VS Code stop moving the keyboard until it is put back. The settings' Troubleshooting says so and puts it in the user's VS Code shortcuts with a button (`ElectronShortcuts.cs`: the Start menu's, the taskbar's and the desktop's that start Code.exe), and shows where the keyboard's log is
